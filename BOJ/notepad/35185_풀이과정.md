# 백준 35185 - 바바는 너야 풀이 과정

## 문제 요약

- 1×N 게임판에서 바바(B)가 깃발(F)에 도달하는 게임
- L: 왼쪽 이동, R: 오른쪽 이동 (벽이면 이동 안 함)
- 깃발에 도달하면 **즉시 종료** (추가 명령어 입력 불가)
- **목표**: 주어진 명령어를 **모두 입력한 후** 승리할 수 있는 (B, F) 쌍 찾기

## 핵심 조건

1. 마지막 명령어 실행 후 바바가 깃발 위치에 있어야 함
2. 중간에 깃발에 도달하면 안 됨 (게임이 즉시 종료되므로)
3. B ≠ F (시작 위치와 깃발 위치가 달라야 함)

## 풀이 전략

### 왜 O(N×L) 브루트포스가 안 되는가?

```
N, L ≤ 200,000
O(N × L) = 200,000 × 200,000 = 400억 연산 → 시간초과
```

### 핵심 관찰: 상대 위치 개념

시작 위치가 달라도 **벽에 막히지 않는다면** 이동 패턴(상대적 변화)은 동일하다.

```
예: 명령어 "RRL"
시작=0 기준: 0 → 1 → 2 → 1
시작=3 기준: 3 → 4 → 5 → 4 (모든 위치에 +3)
```

### 두 가지 케이스 분리

**Case 1: 벽에 한 번도 안 막히는 시작 위치가 존재하는 경우**
- 상대 위치만으로 O(L)에 해결 가능

**Case 2: 모든 시작 위치에서 벽에 막히는 경우**
- 벽 근처(B=1, B=N)에서만 시뮬레이션 필요

---

## Case 1: 벽에 안 막히는 경우

### 상대 위치 계산

시작 위치를 0으로 가정하고 명령어 실행:

```
rel[0] = 0 (시작)
rel[i] = i번째 명령어 실행 후 상대 위치
```

예: 명령어 "LRR"
```
rel[0] = 0
rel[1] = -1  (L 실행)
rel[2] = 0   (R 실행)
rel[3] = 1   (R 실행)
```

### 벽에 안 막히는 B의 범위

실제 위치 = B + 상대 위치

벽에 안 막히려면:
- `B + min(rel) ≥ 1` (왼쪽 벽 안 넘음)
- `B + max(rel) ≤ N` (오른쪽 벽 안 넘음)

따라서:
```
B_low = 1 - min(rel)
B_high = N - max(rel)

B_low ≤ B ≤ B_high 범위에 유효한 B가 있으면 벽에 안 막힘
```

### 답 존재 조건

1. `final_rel ∉ {rel[0], rel[1], ..., rel[L-1]}` (최종 위치가 중간 경로에 없음)
2. `final_rel ≠ 0` (B ≠ F)

조건 만족 시:
```
B = B_low
F = B + final_rel
```

---

## Case 2: 벽에 막히는 경우

### 왜 B=1과 B=N만 확인하면 되는가?

벽에 막히는 효과는 **경로를 압축**시킨다.

```
예: N=5, 명령어 "LLL"

B=3 (벽에 안 막힘): 3 → 2 → 1 → 0(벽 밖) ← 불가능
B=2 (벽에 막힘):    2 → 1 → 1 → 1 (왼쪽 벽에서 정지)
B=1 (벽에 막힘):    1 → 1 → 1 → 1 (처음부터 벽)
```

**핵심**: 벽에 막히면 경로가 더 좁은 범위에 갇힌다.

- B=1에서 시작하면 왼쪽으로 최대한 막힌 상태
- B=N에서 시작하면 오른쪽으로 최대한 막힌 상태

이 두 극단 케이스에서 답이 없으면, 중간 B에서도 답이 없다.
(중간 B는 벽에 덜 막히므로 더 넓은 범위를 방문 → 조건 만족이 더 어려움)

### 시뮬레이션

B=1과 B=N 각각에서 O(L) 시뮬레이션:
- 중간 경로 집합 저장
- 최종 위치가 중간 경로에 없고, B ≠ F면 성공

---

## 전체 알고리즘

```
1. 상대 위치 배열 계산 (O(L))
2. min_rel, max_rel 계산

3. Case 1 체크:
   if B_low ≤ B_high:
       if final_rel ∉ mid_set and final_rel ≠ 0:
           return WIN (B_low, B_low + final_rel)

4. Case 2 체크:
   B=1에서 시뮬레이션 → 조건 만족하면 WIN
   B=N에서 시뮬레이션 → 조건 만족하면 WIN

5. 모두 실패하면 DEFEAT
```

---

## 시간복잡도 분석

| 단계 | 복잡도 | 설명 |
|------|--------|------|
| 상대 위치 계산 | O(L) | 명령어 한 번 순회 |
| min/max 계산 | O(L) | 위와 동시에 |
| mid_set 생성 | O(L) | rel 배열을 set으로 변환 |
| Case 2 시뮬레이션 | O(L) × 2 | B=1, B=N 각각 |

**총 시간복잡도: O(L)**

## 공간복잡도 분석

| 자료구조 | 크기 | 설명 |
|----------|------|------|
| rel 배열 | O(L) | 상대 위치 저장 |
| mid_set | O(L) | 중간 경로 집합 |
| path (시뮬레이션) | O(N) | 방문 위치 (최대 N개) |

**총 공간복잡도: O(L + N)**

## 예제 분석

### 예제 1: N=5, "LRR"

**Case 1 분석:**
```
상대 위치: [0, -1, 0, 1]
min_rel = -1, max_rel = 1

B_low = 1 - (-1) = 2
B_high = 5 - 1 = 4
→ 2 ≤ B ≤ 4 범위 존재

mid_set = {0, -1, 0} = {0, -1}
final_rel = 1
1 ∉ {0, -1} ✓
1 ≠ 0 ✓

B = 2, F = 2 + 1 = 3
```

**출력: WIN 2 3**

### 예제 2: N=4, "LRLR"

**Case 1 분석:**
```
상대 위치: [0, -1, 0, -1, 0]
min_rel = -1, max_rel = 0

B_low = 1 - (-1) = 2
B_high = 4 - 0 = 4
→ 2 ≤ B ≤ 4 범위 존재

mid_set = {0, -1}
final_rel = 0
0 ∈ {0, -1} ✗ → Case 1 실패
```

**Case 2 분석:**
```
B=1 시뮬레이션:
1 → L → 1(벽) → R → 2 → L → 1 → R → 2
중간 경로: {1, 2, 1} = {1, 2}
최종: 2
2 ∈ {1, 2} ✗

B=4 시뮬레이션:
4 → L → 3 → R → 4 → L → 3 → R → 4
중간 경로: {4, 3}
최종: 4
4 ∈ {4, 3} ✗
```

**출력: DEFEAT**

## 반례 분석: N=3, "LR"

**108ms 코드 (오답):**
```
상대 위치: 0 → -1 → 0
check = {0, -1}
final p = 0
0 ∈ {0, -1} → DEFEAT
```

**우리 코드 (정답):**
```
Case 1:
min_rel = -1, max_rel = 0
B_low = 2, B_high = 3
final_rel = 0 → 0 ∈ mid_set ✗

Case 2:
B=1 시뮬레이션:
1 → L → 1(벽) → R → 2
중간 경로: {1}
최종: 2
B=1 ≠ F=2 ✓
2 ∉ {1} ✓
→ WIN!
```

**차이점**: 108ms 코드는 벽에 막히는 케이스를 고려하지 않음.
벽에 막히면 실제 경로가 상대 위치 경로와 달라질 수 있다.

## 최종 코드

```python
import sys
input = sys.stdin.readline

N, L = map(int, input().split())
commands = input().strip()


def simulate(start):
    """start 위치에서 시뮬레이션하여 (최종위치, 중간경로집합) 반환"""
    pos = start
    path = {start}

    for i in range(L - 1):
        cmd = commands[i]
        if cmd == 'L':
            if pos > 1:
                pos -= 1
        else:
            if pos < N:
                pos += 1
        path.add(pos)

    # 마지막 명령 실행
    if commands[-1] == 'L':
        if pos > 1:
            pos -= 1
    else:
        if pos < N:
            pos += 1

    return pos, path


def check(B, F, path):
    """B에서 시작해서 F에 도달하는 게 유효한지 확인"""
    return B != F and F not in path


def solve():
    # === Case 1: 벽에 한 번도 안 막히는 경우 ===
    rel = [0]
    pos = 0
    min_rel, max_rel = 0, 0

    for cmd in commands:
        if cmd == 'L':
            pos -= 1
        else:
            pos += 1
        rel.append(pos)
        if pos < min_rel:
            min_rel = pos
        if pos > max_rel:
            max_rel = pos

    B_low = 1 - min_rel
    B_high = N - max_rel

    if B_low <= B_high:
        mid_set = set(rel[:-1])
        final_rel = rel[-1]

        if final_rel not in mid_set and final_rel != 0:
            B = B_low
            F = B + final_rel
            print("WIN")
            print(B, F)
            return

    # === Case 2: 벽에 막히는 경우 ===
    F, path = simulate(1)
    if check(1, F, path):
        print("WIN")
        print(1, F)
        return

    F, path = simulate(N)
    if check(N, F, path):
        print("WIN")
        print(N, F)
        return

    print("DEFEAT")


solve()
```

---

## 배운 점

1. **상대 위치 활용**: 시작점이 달라도 패턴이 같으면 상대 위치로 일반화 가능
2. **케이스 분리**: "벽에 막힘/안 막힘"으로 나누어 각각 최적 처리
3. **극단 케이스 활용**: 벽에 막히는 경우 B=1, B=N만 확인해도 충분
4. **반례 검증의 중요성**: 간결한 코드가 항상 정답은 아님
